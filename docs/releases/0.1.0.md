# Review Kit 0.1.0

Review Kit 0.1.0 is the first release of `rkc`, a CLI that publishes and updates GitLab code reviews from an agent's policy assessment.
Use the [build identity](../distribution.md#build-identity) to identify the exact executable.

## Review runs

A review run captures the merge request, committed source, diff and supported conversation.
It freezes one complete assessment, with each policy and its outcome recorded once.
The [CLI guide](../../crates/bin/cli/README.md#review-runs) defines commands, runtime files and continuation.

The agent reads policy skills, decides applicability and supplies judgments and evidence.
`rkc` checks declared consistency without loading policy definitions.
Acceptance cannot prove complete policy discovery or correct reasoning.
`rkc` validates an open or uncertain blocking finding only with an independent [confirmation](../../crates/bin/cli/README.md#finding-confirmations).

Publication retains finding IDs and discussions across fixes, withdrawals and recurrence.
Each effect is read back before publication continues.
Interrupted publication resumes from the run's frozen inputs and retained publication state.
A follow-up review can run in a new environment once the reviewer's latest round on GitLab is finished.
The [publication reference](../../crates/bin/cli/README.md#publication-and-recovery) defines permissions, retry limits and recovery.

A blocked assessment can communicate validated findings while an unrelated policy evaluation remains unavailable.
Its final summary stays blocked; unfinished comments retain pending or partial status.
The [application contract](../../crates/lib/application/README.md#publication-and-recovery) defines eligibility, history and recovery.

## Comment presentation

Default finding comments show the explanation, optional suggestion, severity and policy name.
Transition replies begin with a short status such as **Fixed.**.
Summaries show the decision and findings first.
Each earlier round follows in its own collapsed section, and a last collapsed section holds the current round's review details and policy results.

Saved data is compact and hidden in rendered comments. It remains public in raw comment bodies.
Schemas and templates are embedded in the executable.
Caller-owned profiles can change presentation without rebuilding.
The [profile guide](../render-profiles.md) defines editing, selection and supported rendering contracts.

## Configuration, logs and progress

The CLI loads trusted settings from its application home and supports explicit JSON configuration.
The [configuration reference](../../crates/bin/cli/README.md#trusted-configuration) defines selection and retained publication state.
Structured redacted operation logs use newline-delimited JSON at the configured destination.
The [logging preferences](../../crates/bin/cli/README.md#logging-preferences) define default file delivery and stderr fallback.
The [logging guide](../../crates/lib/observation/README.md) describes fields, disclosure rules and external collection.

Long commands report plain progress lines on stderr by default.
Stdout remains the structured command result.
The [progress reference](../../crates/bin/cli/README.md#progress-output) defines terminal-aware and off modes.

## Installation

The [installation guide](../distribution.md) covers archive verification, installation, upgrades and rollback.
`rkc --version` returns `rkc 0.1.0`; `BUILD.json` records the source commit, executable checksum and build environment.
Keep the run directory, publication state and selected profile together during unfinished publication.
The [retained-state contract](../render-profiles.md#retained-state-compatibility) defines supported formats and recovery requirements.

## Scope and limits

- The binary targets Linux x86_64 with glibc. Runtime checks cover Rocky Linux 9, Ubuntu 24.04 LTS and Ubuntu 26.04.1 LTS.
- Provider verification uses the pinned local GitLab CE container and disposable merge requests.
- GitLab.com, other GitLab deployments and other operating systems require separate verification. GitHub reviews are unsupported.
- The agent supplies judgments and evidence. Review Kit validates those inputs and provider effect plans.
- Commands sharing publication state use a local review lock. Separate state roots or machines require caller serialization.
- Recovery retains exact intent, original authority and one controlled creation retry. A late original can still create a duplicate.
- [Conservative recovery](../../crates/bin/cli/README.md#uncertain-writes) disables ambiguous resends.
- Provider readback establishes observed state without proving which request caused it. Publication is not an atomic transaction.
- Shell and wire compatibility with other review tools is unverified.

The [distribution gates](../distribution.md#distribution-gates) define source, package and public-download checks.
The Rust crates are not published on crates.io.
Review Kit is available under MIT or Apache-2.0.
Both license texts and dependency notices are retained in the package.
