# Review Kit 0.1.1

Review Kit 0.1.1 changes the default summary layout and limits the conversation check before publication.
It also records each captured note author's username and bot status.
Commands and configuration are unchanged.
The captured conversation format changes; read [upgrade and rollback](#upgrade-and-rollback) before you install.
The [0.1.0 release notes](0.1.0.md) describe the rest of `rkc`.
Use the [build identity](../distribution.md#build-identity) to identify the exact executable.

## Summary layout

The current round is visible: its decision, recap, limitation, status and findings.
Each earlier round has its own collapsed section, oldest first.
That section shows the round's decision in its label and holds only its findings table.

One collapsed `Review details` section closes the summary.
It holds each round's commit, scope, depth, workflow, limitations and policy tables under a `Round N` heading.
The current round comes first, then the earlier rounds in the order of their sections.
The [renderer contract](../../crates/lib/infrastructure/json2md-adapter/README.md#default-presentation-and-safety) defines the layout.

## Conversation check before publication

Before the first write, publication compares only the existing objects that it writes to.
They are the reviewer's summary note and each finding thread that receives a transition reply, an answer, a resolve or a reopen.
A change to one of them still fails with `conversation_changed`.
Changes outside them no longer stop publication.
These include comments by other people or bots elsewhere, the reviewer's threads without a planned effect, replies to the summary and title or description edits.
The publication engine refuses a round that would write to an existing object outside the compared set (`uncompared_write`, exit `3`).
A plan that writes nothing has no objects to compare, so it settles as `no_changes` without writes.
The [publication reference](../../crates/bin/cli/README.md#publication-and-recovery) defines the compared objects and the check order.

## Note author accounts

`rkc run start` writes `review-conversation.json` version 2.
Each captured note records its author's username and GitLab bot status beside the numeric user ID.
`null` means unknown.
`run start` asks GitLab for the bot status of at most 50 distinct authors; planning and publication ask nothing.
Comparisons identify authors by numeric ID only.
The [captured conversation reference](../../crates/bin/cli/README.md#captured-conversation) defines the fields and the lookup limits.

## Upgrade and rollback

0.1.1 reads the review runs of 0.1.0.
Other retained formats are unchanged; the [state compatibility contract](../render-profiles.md#retained-state-compatibility) lists every format.
An intact conversation in a version that the executable cannot read fails with `newer_run_document`, and `status` reports its retained files as `newer`.

The embedded rendering profile changes, so its fingerprint changes.
An unfinished round continues only with the exact profile that rendered it.
While a round that 0.1.0 rendered is pending or partial, 0.1.1 with its default profile refuses to continue it (`render_profile_changed`).

To continue such a round, do one of these:

- Finish the round with 0.1.0 before you upgrade.
- Export the 0.1.0 profile with the 0.1.0 executable: `rkc render-profile export --dir DIRECTORY`.
  Select that profile with `--render-profile DIRECTORY/profile.json` or `render_profile` in configuration until the round finishes.

Completed rounds need no action.
The next published round renders the whole summary in the new layout, including earlier rounds.
A caller-owned profile keeps its fingerprint and renders as before.
The [rendering profile guide](../render-profiles.md#recover-an-interrupted-attempt) describes recovery with a restored profile.

0.1.0 cannot read the version 2 conversation of a run that 0.1.1 started, and reports that run as damaged.
Before you roll back, finish or stop every run that 0.1.1 started.
Keep 0.1.1 for any such run that owns unfinished publication, and finish that publication with it first.
The [rollback procedure](../distribution.md#upgrade-and-rollback) and the [captured conversation reference](../../crates/bin/cli/README.md#captured-conversation) describe the effects on other runs.
`rkc --version` returns `rkc 0.1.1`.

## Verification and limits

The [distribution gates](../distribution.md#distribution-gates) define the source, package and download checks for this release.
Runtime checks cover Rocky Linux 9, Ubuntu 24.04 LTS and Ubuntu 26.04.1 LTS on x86_64.
Provider checks use the pinned local GitLab CE server and disposable merge requests.
The [0.1.0 scope and limits](0.1.0.md#scope-and-limits) apply unchanged.
