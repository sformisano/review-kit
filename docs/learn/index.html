Why an entity?

Finding has an identity that survives changes to its state. That is what makes it an entity.

F1 is scoped to the review subject and reviewer. It is separate from GitLab’s discussion and note IDs.

The agent records each rule once

The agent reads the linked skills and declares the policies it assesses. Review Kit adds no policies. One assessment contains each policy, its relevance and its result. rkc accept freezes that complete review.

review-assessment.draft.json holds one row per policy: identity, required flag, reason and outcome. The outcome is excluded, unresolved, satisfied, violated or blocked. Missing judgments prevent acceptance.

↓ AssessmentPolicies::new
Skills and results

The agent reads ordinary skills and decides which rules apply. PolicyId identifies each rule in the assessment.

AssessmentPolicies carries the declared IDs and display names. A PolicyEvaluation records satisfied, violated, or blocked.

F1 describes a particular problem. Its policy evaluation describes the judgment about the rule. They share a PolicyId.

Acceptance checks the single assessment without loading skills or definitions. It cannot detect an omitted policy or show that a decision is right. Missing criteria or evidence require an explicit limitation. See the checkpoint contract.

How the application gets here

  1. AssessmentPolicies::new

    Take the policy IDs and public names from the accepted assessment and validate them.

  2. assessment::prepare

    Use the provider snapshot and prior findings to create slots for fresh judgments and reassessments.

  3. assessment::complete

    Require those inputs, check the declared coverage, and construct the domain assessment.

Why a value?

An Assessment has no independent identity. It is an immutable record for a reviewed revision; equality compares its complete contents.

It owns its findings. Changing a separate copy of F1 leaves the earlier assessment unchanged. A follow-up builds another assessment.

Publish the review.

The domain records judgments without I/O. The application plans and verifies effects through ports. The GitLab adapter performs HTTP calls.
